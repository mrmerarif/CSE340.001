Good—this is exactly the kind of moment where learning happens ??
You’re on the right track thinking about how the value is handled, but there’s an important difference here.
<%= %> ? escapes the output (safe: prevents HTML/script injection)
<%- %> ? does NOT escape the output (renders raw HTML)
So if project.name contained something like:
<strong>My Project</strong>
<%= project.name %> would display it as text:
"<strong>My Project</strong>"
<%- project.name %> would actually render it as bold text on the page
This matters a lot for security—using <%- %> with user-generated data can open the door to XSS (cross-site scripting) attacks.

Let’s tighten it up just a bit:
<%- %> ? use this only when you intentionally want to render HTML (and you trust the content)
<%= %> ? use this by default for most cases, especially when displaying data from a database or users, because it escapes HTML and keeps your app safe
So a good rule of thumb:
If the content is plain data (like names, titles, etc.) ? use <%= %> ?
If the content is trusted HTML (like formatted content you created yourself) ? you can use <%- %> ??
